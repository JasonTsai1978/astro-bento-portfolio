*「養龍蝦」系列番外。[第 3 集](/blog/lobster-ep3-letting-go-zh/)講我九月把龍蝦退租，這集是後續。*

先講結論：10/17 早上，我收到 Zeabur 創辦人寄來的信，平台要結束營運了。12/1 起陸續停機，12/31 全部關閉。

龍蝦一個月前就退租了，我本來以為這件事跟我無關。查了一下才發現，八月出資安事件的時候，龍蝦其實還在線上。

## 發生什麼事

以下只引官方說法：

- **8/27，第一次入侵。** 共享叢集上，有位用戶部署的 NextChat 有漏洞，攻擊者從那裡進來，一路讀到平台的資料庫。部分專案環境變數的名稱和值被讀走，裡面有 AI 服務的 API key、雲端憑證、資料庫密碼。官方承認，當時的監控沒有偵測到，是 8/28 有用戶回報 key 被盜用才發現。（[官方事後報告](https://zeabur.com/zh-TW/blogs/august-2026-security-incident)）
- **10/14，第二次入侵。** 官方一開始說只影響共享叢集，幾小時後更正：Google Cloud 上的部分專用伺服器也被存取，平台資料庫可以被讀取。（[狀態頁](https://status.zeabur.com/incident/1091243)）
- **10/17，宣布結束營運。** 信裡說，兩次資安事件讓團隊看清自己在安全與維運上的不足；另一方面，AI 也讓部署本身越來越容易。

信裡有一句讓我愣了一下：「從 n8n、OpenClaw 到 Vibe Coding，AI 為雲端部署帶來了前所未有的需求。」

我就是那波需求的一份子。n8n 新聞 bot 和 OpenClaw 龍蝦，兩個都放在 Zeabur。

## 跟我有什麼關係

龍蝦的設定都放在環境變數裡：模型的 API key，還有幾個服務的登入憑證。八月事件發生時，龍蝦還沒退租。

我沒收到任何事件通知信，但這不代表沒事，因為官方自己承認，第一封通知信把影響範圍判斷錯了。

官方的建議很直接：只要曾經放在 Zeabur 環境變數裡、現在還有效的憑證，全部換掉，包括通知信沒列到的。

## 我做了什麼

- **OpenAI、Anthropic 的 key 都撤銷了。** 兩邊都查過，8/27 之後沒有使用紀錄，也沒有扣款。
- **GitHub token、搜尋服務的 key**，十月初寫這個系列時就已經刪掉了。
- **Zeabur 上的環境變數也清掉了。** 但這只是第一步：被讀走的是當時的值，平台上刪掉，外面那份照樣能用。真正讓它失效，要回到源頭撤銷。
- 剩下的憑證，還在一個一個處理。

## 學到的：退租不等於安全

退租只代表不用再付錢。放在平台上的 key，只要還有效，就還是一把能用的鑰匙。

下次退租，我會照這個順序：

1. 先列出所有放在平台上的憑證。
2. 退租當天就到源頭撤銷，不要等到出事。光刪平台上的變數不算數。
3. 給 agent 用的 key 先設好用量上限，萬一出事，損失有個底。
4. 要求平台刪除帳號和資料，不能只停服務。

第 3 集最後我說，龍蝦也許只是我玩得早了一點。現在連養龍蝦的池子也收了。
