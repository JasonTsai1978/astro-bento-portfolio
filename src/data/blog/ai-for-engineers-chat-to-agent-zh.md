先講結論：AI 用得好不好，差別不在問得多聰明，而在你給它多少背景、讓不讓它自己驗證結果。從網頁問答走到 agent，就是把這兩件事一步一步交出去。

前兩篇（[導入前先問的四件事](/blog/enterprise-ai-coding-tools-zh/)、[從個人實驗到團隊規範](/blog/personal-experiments-to-team-standards-zh/)）是寫給主管的：怎麼選、怎麼管。這篇寫給工程師：怎麼用。

## 現在多數人怎麼用

打開網頁版 ChatGPT 或 claude.ai，貼一段 code，問「這段為什麼錯」「這個語法怎麼寫」。這很有用，我也天天這樣做。

但有三個限制：背景要自己複製貼上，AI 看不到整個專案；它給的答案沒跑過，對不對要自己試；改好的東西還得自己搬回編輯器。問題越大，這三件事越花時間。

## 四個層次

| | 長什麼樣子 | 適合 | 要注意 |
|---|---|---|---|
| 1. 個人版網頁 | 個人帳號的 ChatGPT、claude.ai | 問語法、解釋錯誤訊息、學新東西 | 公司的程式碼不要貼這裡 |
| 2. 企業版 Chat | 公司核准的企業方案 | 一樣是問答，但可以放專案背景、上傳規格文件 | 資料政策比個人版嚴，但還是照公司規定 |
| 3. IDE 內嵌 | 編輯器裡的補完與對話，例如 GitHub Copilot | 寫到一半的補完、局部改寫、解釋眼前這段 | 看得到的範圍有限，大改動容易顧此失彼 |
| 4. Agent | Claude Code、Codex 這類 | 讀整個 repo、改多個檔案、跑 build 和測試、自己修 | 它會執行指令，權限要設好，結果一定要 review |

越往下，AI 拿到的背景越多、能自己做的事越多，你要管的也越多。不是越下面越好，是看工作挑層次。

## 每一層，一個日常例子

**1. 個人版：看懂錯誤訊息。** 拿到一段看不懂的 .NET 例外訊息，或想知道 T-SQL 的 `MERGE` 跟先 `UPDATE` 再 `INSERT` 差在哪。這類問題不碰公司資料，網頁版最快。

**2. 企業版：解讀執行計畫。** 一支查詢突然變慢，把執行計畫和資料表結構丟進公司核准的企業版，問它瓶頸在哪、該不該補 index。常用的 schema 說明放進 Project，之後不用每次重貼。

**3. IDE 內嵌：補 unit test。** 游標停在一個 C# 方法上，請它照現有測試的寫法補幾個邊界案例。範圍就是眼前這個檔案，剛剛好。

**4. Agent：看懂舊程式，再小步重構。** 接手一個沒人記得的舊服務，先請 agent 讀完整個專案，講清楚資料怎麼流、哪裡呼叫資料庫。確認看懂了，再請它把一段重複的邏輯抽出來，改完自己跑 build 和測試。我在家多半用這一層，上一篇有寫我的設定。

## 心態：從「問答」換成「交辦」

到了第 3、4 層，最大的改變不是工具，是你怎麼開口。

問答是「這段怎麼寫？」。交辦是像交代一個新同事：背景是什麼、要做到什麼、怎麼算做完。例如：「這支服務要加一個欄位，資料表在這、相關的 API 在這；改完 build 要過、既有測試要過，不要動到其他模組。」

交辦出去之後，你的角色就變成 reviewer。AI 改了什麼，你要看得懂、說得出為什麼可以合併。看不懂，就不要合併。

## 常見的四個誤區

- **盲信。** AI 講得很有把握，不代表對。沒跑過的，就當作沒驗證。
- **公司的東西貼進個人帳號。** 很方便，但這是最不該發生的事。
- **不給背景。** 只丟一行錯誤就問為什麼，它只能用猜的。多給一點上下文，答案會差很多。
- **一次交辦太大。** 「幫我重構整個模組」很難 review。切小，一次一件，每一步都能檢查。

## 第一週可以這樣開始

不用一次全換。我會建議：

- 先確認公司核准了哪些工具；個人帳號只拿來問跟公司無關的問題
- 挑一件每週都會遇到的小事，例如看錯誤訊息或補測試，固定交給 AI
- 每次交辦都寫清楚「怎麼算做完」
- 自己留一點紀錄：哪類工作好用、哪裡出錯，之後才有東西跟團隊分享

## 最後

AI 不會讓你不用懂程式。它讓懂程式的人，把時間花在判斷，而不是打字。從問答到交辦，練的其實是同一件事：需求講清楚，結果看清楚。
